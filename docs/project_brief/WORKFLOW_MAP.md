# End-to-End Workflow Map

Run the prompts in order. Do not skip the review gates.

| Stage | Prompt | Primary output | Gate before proceeding |
|---|---|---|---|
| 0 | 00_SCOPE_AND_WORKSPACE_AUDIT | Project inventory and scope map | Workspace and source inventory are correct |
| 1 | 01_SOURCE_DISCOVERY_AND_DOWNLOAD | Source inventory, retrieval log | Every download is real, accessible, and catalogued |
| 2 | 02_LITERATURE_REVIEW_AND_GAP | Literature matrix and research-gap memo | Gap is narrow and evidence-supported |
| 3 | 03_QUANTITATIVE_EVIDENCE_DATASET | Data register and comparison dataset | Definitions, dates and comparability are documented |
| 4 | 04_FINAL_PROBLEM_AND_FRAMEWORK | Problem statement and five-pillar framework | Coordinator's requirements are reflected |
| 5 | 05_DEMAND_CASCADE_MODEL_SPEC | Parameter register and equation audit | Units and assumptions are approved |
| 6 | 06_IMPLEMENT_AND_TEST_MODEL | Python model and tests | Model passes tests and outputs are reproducible |
| 7 | 07_RESULTS_SENSITIVITY_AND_FIGURES | Tables, figures and results memo | Results match code and sources |
| 8 | 08_DEPENDENCY_MCDA_AND_ROADMAP | Risk/priority matrix and roadmap | Scores/weights justified or avoided |
| 9 | 09_MANUSCRIPT_PLAN_AND_ABSTRACT | Section evidence map and provisional abstract | No invented results |
| 10 | 10_GENERATE_IEEE_LATEX | LaTeX and compiled review PDF | Build succeeds; references and figures resolve |
| 11 | 11_RED_TEAM_AUDIT | Audit report and correction log | Critical issues resolved |
| 12 | 12_FINAL_REVIEW_AND_PRESENTATION | Submission checklist, slides and Q&A | Human approval and event-rule check |

## Required outputs for the paper
- Literature matrix with authors, year, exact title, method, strength, limitation and pillar.
- Quantitative evidence dataset with source/page/URL, unit, year and evidence status.
- Five-pillar framework diagram.
- AI infrastructure dependency map.
- India–US–China comparison only for comparable indicators.
- Three GPU scenario results.
- Sensitivity analysis.
- At least one documented example of how the framework changes a planning priority.
- Policy roadmap.
- IEEE LaTeX manuscript and bibliography.
- Audit report and open-issues register.
